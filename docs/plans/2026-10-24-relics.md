# 遗物风险与绑定 Implementation Plan

**Goal:** 世界页面可查看15种遗物；全队自动承担风险，个人获取时绑定且每人一件，有限次数逐件损毁。
**Architecture:** 新建 relics.gd 统一目录、实例和描述。Campaign 管理获取、替换、撤离和存档迁移，Rules 消耗战斗实例并在结算回写；界面只提供查看与获取时指定角色。
**Tech Stack:** Godot 4 / GDScript。

1. tests/relics.gd 先验证获取约束、个人替换、次数损毁、存档和旧档迁移，运行确认缺少功能失败。
2. 新增 game/relics.gd，扩充 campaign.gd；保留旧字符串遗物兼容入口，存档升级v4并严格验证实例。
3. rules.gd 接入全队/个人作用范围，攻击、防护、休息、治疗、技能、致命保护、击杀触发，精确扣次数并显示损毁日志。
4. main.gd 与 party_details.gd 展示逐件遗物、独立遗物栏、获取/商店角色选择和替换警告，撤离保留实例。
5. 添加规则和界面回归测试，运行 tests/verify.py，截图检查世界与个人遗物页，记录README规则。

直接在当前工作区增量实现，保留用户已有未提交修改。用户已批准实施，无需阶段性再次确认。
