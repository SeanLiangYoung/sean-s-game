# 陆衡支援组与六区长线复测（2026-10-25）

本轮先修正失败原因归类和自动支援策略，再用未用于调参的新初始种子从零复测。实际游戏自动战斗接入治疗、医师撤离与缩圈避险；模拟中的标记、补给和合法训练策略另做对照。这是**自动决策与真实资源使用的组合修正**，结果不能描述为单纯数值增强，也不是手动玩家通关率。

## 失败原因排查

上轮完整六区共41次失败，37次结束时仍有补给。复查陆衡支援的6次失败，再按团长与失败区域选取其他记录，共冻结20条诊断病例，重放结果仍为20次失败。

- **技能成型**：陆衡支援组有早期零经验战斗减员，也有已学6—7种技能、已有四件共鸣和两个两件共鸣之后的长线失败。不能把所有失败判定为技能未解锁。诊断中把陆衡较省行动点的控制技能、游侠控制分支前置，仍支付全部真实经验与前置成本；相较已修正支援和补给的方案，20条记录只净增加1次通关，但陆衡支援从1/6到3/6，说明该组对学习节奏有局部敏感性。
- **补给与站位**：选取的20条失败有19条结束时剩余补给；首次出现伤亡的战斗中，25名死亡角色有9名死亡时仍有至少90%法力，25名全部对应战斗都仍有补给。一例医师以46生命、40法力进入边境精英战，连续两次推进并普攻，随后承受四次12伤害死亡，补给3份未动。这里主要是站位、行动时机与资源投放问题，不能仅靠增加补给掉落解决。
- **遗物依赖**：部分失败已经具备共鸣，遗物缺失不是充分解释。频率和“成功轨迹中经常出现”不构成因果证据，本轮对事先冻结的热门遗物集合做额外拒选，而不把失败后补发指定遗物算作成功。

上述问题会相互影响：早期支援死亡后，后续真实付费招募的新兵需要重新赚经验；队员数量、法力和出手顺序变化又会改变后续路径与掉落。不会将每条失败强行归入互斥的单一原因。

## 落地调整与边界

`game/rules.gd`增加只基于公开敌人位置、普攻射程、攻击力与防护的保守受击压力估计。自动战斗在明显伤损或即将承受集火时，优先使用实际可施放的治疗；医师无合适治疗时寻找较安全的撤离位置，普通移动也避免主动进入高压位置。后续又对团长加入移动暴露检查，避免为了未来攻击而连续推进、耗尽行动点后进入明显集火区；处在危险中时仍允许向较低压力的位置移动。该估算不完整模拟敌方技能、行动顺序与实际集火选择，不能保证绝对安全。所有施法仍经真实规则支付行动点与法力。

独立复查发现初步撤离方案会退到本轮即将缩圈的边缘。已补充第3回合、半径3、低血医师的失败回归，并让医师撤离与普通移动共用缩圈安全判断。首领预警避让仍在治疗前处理。当前没有加入“自动接近受伤队友至施法距离”的完整支援寻路，压力估计也不是未来敌方实际行动的精确预言。

模拟侧保留原决策作为对照，并可选用同一公开支援判断。修正标记后没有合法即时攻击跟进却继续耗蓝的情况。野外较早处理单人的明显生命/法力亏空，并尽量留一份补给用于战斗；战内可用真实补给在预计集火致死前处理，而不只等固定残血比例。恢复比例、使用射程和行动点成本均经真实接口执行。

训练比较使用两条通过前置和经验支付的顺序。主测保留原来的广泛解锁顺序；留出组改为陆衡与游侠较早取得控制分支的顺序。没有预先给技能、遗物、额外装备、经验、银币或补给；没有复活、读档重试或突破撤离保留上限。

## 诊断对照与中间版本（v2）

修复缩圈前的初步诊断对照：20条原失败记录，只启用支援修正后8条通关；再启用较早用补给后13条通关；再换控制优先训练后14条通关。陆衡支援分别为0/6、2/6、1/6、3/6，完整保留补给调整使该组变差的反例。这些是针对已知失败病例的诊断，**不是一般通关率**；初稿源码单独存档。

医师修正版（v2）用第一批新种子验证，主测前后各72次：三团长×四种真实队伍优先级×两种可见信息策略×三初始种子；12个独立初始种子块，跨团长与策略配对。另有12个不重合初始种子块的72次留出验证，并使用另一条合法训练路线。因此留出组同时改变种子和训练顺序，不能单独归因于其中一项。

每条记录均从真实六名初始成员、八件装备、40银币、3份补给、零经验、一级基础技能和零遗物开始；已解锁团长可选，但不导入解锁档的成长资源。按边境、林地、荒原、冻原、沼地、废墟连续推进，永久死亡、现存后备与实际付费招募持续继承。所谓队伍类型是初始出战优先级，伤亡后不凭空补齐原阵容。

固定新旧策略后，用相同初始种子进行对照；决策与伤亡变化会使后续随机数、路径和奖励分化，不承诺六区逐节点相同掉落。该中间版新种子区间为2026110100加队伍偏移与样本序号；留出区间为2026120100，均不同于上一轮种子。完整参数在冻结病例文件与计划中。

主测结果：28/72（38.9%）→49/72（68.1%），配对27条由败转胜、6条由胜转败。陆衡支援1/6→4/6；12个团长与队伍分组均有完整六区通关，陆衡突击仍为2/6。按团长为沈烬16/24、闻笙17/24、陆衡16/24；按策略为自适应22/36、偏重遗物27/36。不能据此宣称两种策略在任意种子都同强。

主测失败从44条减至23条，其中仍剩补给的失败由40条减至14条。首个伤亡发生率也下降，但依然较高；永久减员、控制覆盖和后续续航仍影响通关。该结果支持先修正支援与资源投放，尚不足以把每种角色组合调成相同胜率。

v2另一批种子与替代训练通过58/72，陆衡支援4/6。事先冻结的24条热门集合拒选通过16/24，但三团长支援组共0/6，暴露出远程增伤遗物掩盖团长冒进的问题：团长80生命、24法力，连续移动耗完4行动点，没有攻击，随后被首轮集火击杀。此时不能把v2作为最终完成结果。

新增团长移动暴露回归，观察失败后加入同源检查；原来6条支援拒选记录复跑后2条走完六区（闻笙、陆衡各1条），仍保留其他失败。针对已见种子的改善仅作为诊断，不作泛化证明。

## 最终团长避险版（v3）与全新种子

v2完整数据及源码保留。团长检查落地后，再冻结此前从未用于调整的2027010100系列初始种子，前后各72次完整六区对照，仍沿用原训练顺序。最终版主测35/72（48.6%）→56/72（77.8%），27条由败转胜、6条由胜转败。陆衡支援3/6→6/6；每个团长与队伍分组的6条记录只有3个初始种子，另一个维度是两种策略，不能当作6次独立掉落。

最终计划还包含同72条病例全部同时拒选热门集合、主测每组第一个样本的配对替代训练24次，以及2027020100系列4个独立初始种子块的24次留出验证。基线72、主测72、拒选72、替代训练24、留出24，共264条开荒尝试记录；主测12个初始种子块，另4个为不重合留出，训练和拒选复用配对种子。最终主测12个团长×队伍分组均至少3/6通关，三团长分别为沈烬18/24、闻笙19/24、陆衡19/24。失败37条→16条，失败时仍有补给31条→3条。仍有5条边境、1条林地、3条冻原、1条沼地与6条废墟失败，不能称全面平衡。

替代训练23/24，对应原顺序20/24（3条由败转胜、无由胜转败），两条顺序都存在通关路径。独立留出19/24；陆衡支援在其中一个初始种子、两策略下0/2，因此仍需保留该组脆弱性，而不能用主测6/6替代这一结果。为评估这是否只是单个种子，保持最终规则不变，另外预先冻结5个新种子2027030300—2027030304，两条训练各跑10次，专项结果为原顺序8/10、控制优先8/10，二者这次通过/失败的配对完全相同；没有围绕失败种子再调规则。专项新增20条记录，连同正式计划共284条开荒尝试，覆盖12个主测、4个常规留出、5个陆衡专项留出的独立初始种子块；训练、团长、策略与拒选维度均有配对，不能把284条当成284次独立掉落。

完整72条热门集合拒选通过48/72，原配对56/72；7条由败转胜、15条由胜转败。12个团长×队伍分组仍都有通关；陆衡支援5/6，沈烬支援4/6、闻笙支援5/6。66条原轨迹首领前实际持有过被拒集合物品，拒选后46/66成功，原配对54/66。其余6条单独保留，不把未取得的成功当有效剥离证据。这支持三位团长及各队伍有替代路径，仍显示热门遗物与后续路线会显著影响结果。

## 遗物拒选、审计和复跑

拒选名单沿用前轮已经确定的dusk_2、hunt_3、hunt_4，正式结果出来前冻结。最终版对全部72条主测病例进行拒选，不按是否成功筛选；中间v2使用每组第一个样本的24条记录，分开保留。拒选只跳过真实奖励与商品，不重掷货架或补发物品。报告另列原轨迹在首领前真正持有集合物品的子组，避免把原本未遇到物品的成功当作有效拒选证据。

所有正式结果保留战斗初始阵容、生命法力、技能、逐回合状态、事件与结尾，以及奖励、购物、训练、补给和招募账目。摘要脚本校验零成长初始状态、训练扣费与真实战斗所得经验加路线事件经验上界、购物收支、拒选物品未取得、整轮结局、病例哈希和源文件哈希。旧日志未记录研习事件子类型，事件经验只能按每个已访问事件最多20经验审计上界；不声称每个事件收入都有精确独立账目。

冻结基线与正式最终源码差异为生产`game/rules.gd`和模拟`tools/relic_mix_simulation.gd`（模拟移动接入共享医师及团长安全判断）。其余成长、掉落、敌人和装备源码相同；决策开关也在每条病例中明确记录。初稿诊断与正式修复版分开保存，初稿中断的未完成正式进程不计入结果。

- 汇总：`artifacts/longline-summary.json`包含中间版和最终版，最终版另存`artifacts/longline-prospective-summary.json`，生成器`tools/summarize_longline.py`。
- 原始记录：最终为`artifacts/longline-prospective-{baseline,final,refusal,alternative,holdout}-{shen,wen,lu}.json`；中间版本为`longline-{diagnostic,new-baseline,new-final,holdout-final,refusal}-{shen,wen,lu}.json`；诊断分项为`longline-{support,supply,training}.json`，已知支援拒选重放为`longline-targeted-{shen,wen,lu}.json`；陆衡额外留出为`longline-lu-{broad,control}-holdout-lu.json`，冻结输入与计划同目录保存。
- 参数：`artifacts/longline-*-cases.json`、原计划`artifacts/longline-plan.json`及最终冻结计划`artifacts/longline-prospective-plan.json`。
- 冻结模拟源码：`artifacts/longline-baseline-sources.zip`、`longline-ablation-sources.zip`、`longline-v2-sources.zip`、`longline-final-sources.zip`，各有源文件清单与校验值；并非含完整界面资源的发行包。

解压对应源码包后，以Godot 4.7.2运行以下命令；团长替换成wen、lu覆盖其余分组。基线用于prospective-baseline、new-baseline与diagnostic，初稿包用于support/supply/training，v2包用于new-final/holdout-final/refusal，最终包用于prospective-final/refusal/alternative/holdout和targeted。汇总用`python3 tools/summarize_longline.py --prospective`，合并保留v2与v3，旧版本摘要另存`longline-v2-summary.json`。

```sh
Godot --headless --path <解压目录> --script res://tools/simulate_longline.gd -- --label=prospective-final --cases=res://artifacts/longline-prospective-final-cases.json --captain=shen
Godot --headless --path <解压目录> --script res://tools/simulate_longline.gd -- --label=prospective-holdout --cases=res://artifacts/longline-prospective-holdout-cases.json --captain=shen
Godot --headless --path <解压目录> --script res://tools/simulate_longline.gd -- --label=prospective-refusal --cases=res://artifacts/longline-prospective-refusal-cases.json --captain=shen
```

固定操作水平、有限初始种子、两条训练顺序和一个拒选集合不能覆盖所有110件遗物、全部技能排列与人类操作。本轮证据用于支持多种组合存在替代通关路径，并明确保留剩余弱组，不能证明整个游戏已无任何遗物依赖。

摘要审计全部正式记录通过，源文件运行中无变更。冻结最终源码包独立解压后，陆衡支援2027010301、自适应策略的六区轨迹完整复跑：19场战斗通关，包含事件、奖励、成长与资源账目的整个结果对象与原记录完全一致。实验完成时的工作区游戏源码也与当时冻结最终版逐文件一致；后续管理界面和遗物发现改动不属于该冻结版本。
